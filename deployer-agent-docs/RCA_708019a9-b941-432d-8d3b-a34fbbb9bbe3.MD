# RCA — Chat Review "chat-propose-account" failing on production

## Requested investigation
The chat-review "No Category" flow (`POST /api/companies/{cid}/reviewv2/chat-propose-account`,
`chat_propose_account` in `backend/routes/reviewv2.py`) instantly rejects every input on
production. The hypothesis handed to me was one of four Secrets/balance causes:
missing `EMERGENT_LLM_KEY`, zero balance, `emergentintegrations` `ImportError`, or a
prod-vs-preview key mismatch — with an expected fix of "Secrets update or balance top-up,
no code change."

## Headline finding — NONE of the four is the cause
The reported code path **does not exist in the deployed production image.** The symptom cannot
be a bad/empty/quota-exhausted `EMERGENT_LLM_KEY`, because the function that calls the LLM was
never shipped to this deployment.

## Evidence (all read-only, on deployment `aifinance-hub-6`, run `708019a9-...`)

1. **This deployment has exactly ONE deploy run, ever — the initial deploy on 2026-07-22.**
   `describe_deployment_state` → `recent_runs` has a single entry (type `initial`,
   completed `2026-07-22T10:06:34Z`). There has been no redeploy since. The user states the
   reviewv2 feature/rejection string appeared **Sept 18** — i.e. ~2 months AFTER this build.

2. **The reviewv2 / chat-propose feature is absent from the deployed source.** I spawned an
   eph sandbox from THIS run's archived build source (`/app/scratch`) and grepped the whole tree:
   - `backend/routes/reviewv2.py` → does not exist (the `routes/` dir has no `reviewv2*`).
   - `grep -rn 'chat_propose_account|chat-propose-account'` over `backend/` → **0 matches.**
   - `grep -rn "couldn't propose a category"` over backend AND `frontend/src` → **0 matches.**
   - `grep -rln 'reviewv2'` over all .py/.js/.jsx/.ts/.tsx → **0 matches.**
   Note: the user asserts `reviewv2.py` is present on HEAD/preview. Its total absence from
   this run's archived source is positive proof the deployed image is the OLD pre-feature build,
   not current HEAD.

3. **No `/api` traffic and no such exception in logs.** `fetch_app_logs` over the full 24h
   Loki window: excluding `/health`, there are **0** log lines — the only backend output is
   `GET /health ... 404` liveness spam. A grep for `chat_propose_account LLM call failed`
   (and for Authentication/RateLimit/ImportError/402/401) → 0 matches. That log line cannot
   appear because the function isn't in the image.

4. **`EMERGENT_LLM_KEY` IS set (answering Q1).** `list_secrets` on the active run:
   `EMERGENT_LLM_KEY` present, `is_empty:false`. (Value never revealed; I cannot read balance,
   and cannot compare the value to preview — I only get name + emptiness. The
   `matches_expected:false` you may see is only because I compared it against an empty string.)

5. **`emergentintegrations` IS installed (answering Q4).** `backend/requirements.txt` pins
   `emergentintegrations==0.2.0`; the Dockerfile installs it from the Emergent CloudFront index
   (`EMERGENT_PYPI_INDEX=https://d33sy5i8bnduwe.cloudfront.net/simple/`). Caveat: the install
   uses `pip install --no-dependencies`, so transitive deps must be pinned explicitly in
   requirements.txt — worth keeping in mind for the *real* deploy, but not the cause here.

6. **`app.smartbookssoftware.ai` is NOT attached to this deployment.** `list_domains` and
   `check_domain_status` both return an empty domain list. This deployment serves only
   `https://aifinance-hub-6.emergent.host`. Whatever is answering at `app.smartbookssoftware.ai`
   is being served by something OTHER than the deployment I am scoped to.

## Root cause
Two things, both of which make the "Secrets/balance" theory a red herring:

- **(A) Stale production build.** The live production image for `aifinance-hub-6` is the
  initial 2026-07-22 build and has never been redeployed. It predates the entire
  reviewv2/chat-propose feature; the endpoint, the `chat_propose_account` function, the
  `EMERGENT_LLM_KEY` LLM call, and even the rejection string are all absent. Hitting
  `/api/companies/{cid}/reviewv2/chat-propose-account` on this image cannot reach an LLM
  because the route does not exist.

- **(B) Domain/scope mismatch.** `app.smartbookssoftware.ai` — the URL where the symptom is
  reproduced — is not linked to this deployment. If that domain currently renders the reviewv2
  chat flow at all, it is served by a *different, newer* deployment than the one this RCA was
  scoped to. Diagnosis of that domain must be run against whichever deployment actually serves it.

## Fix (NOT a secrets update and NOT a balance top-up)
1. **Redeploy current HEAD to production.** The feature has never been deployed here. Only a
   fresh build/redeploy will ship `reviewv2.py` + `chat_propose_account`, at which point the
   already-present `EMERGENT_LLM_KEY` will actually be exercised. (If, after redeploy, the LLM
   call then fails, re-run this diagnosis — the swallowed-exception log line will exist by then.)
2. **Confirm which deployment serves `app.smartbookssoftware.ai`.** It is not attached to
   `aifinance-hub-6` (no custom domains here; live URL is `aifinance-hub-6.emergent.host`). If a
   separate/newer deployment serves that domain, re-run the RCA scoped to that deployment.

## Verified vs inferred
- Verified: single July-22 run; feature/route/string absent from this run's source; no /api
  traffic + no exception in 24h logs; `EMERGENT_LLM_KEY` present & non-empty;
  `emergentintegrations` pinned; zero custom domains on this deployment.
- Inferred / not checkable with my tools: Universal Key balance (no tool); exact prod-vs-preview
  key value equality (values never exposed); which deployment currently serves
  `app.smartbookssoftware.ai`.
